# Инструкции для AI-агента

## 1. Документация проекта

Перед выполнением каждой задачи обязательно изучать:

- `.agent/context.md` — контекст проекта, стек, архитектура и принятые решения.
- `.agent/rules.md` — правила работы и ограничения на изменения.
- `specs/spec.md` — спецификация продукта и требования к функциональности.

Считать эти документы источником требований к проекту. Если какой-либо файл отсутствует или необходимая информация в нём не определена, не придумывать решения, противоречащие уже принятым договорённостям.

При необходимости уточнять требования у владельца проекта до внесения изменений.

## 2. Работа с кодом

- Перед изменениями изучать существующую реализацию и связанные файлы.
- Выполнять только задачу, поставленную владельцем проекта.
- Вносить минимально необходимые изменения.
- Не добавлять зависимости, библиотеки и инструменты без предварительного согласования.
- Не переписывать большие компоненты, страницы или модули без прямого указания.
- Не проводить попутный рефакторинг и не менять поведение приложения без необходимости.
- Соблюдать упрощённую архитектуру FSD, описанную в контексте проекта.
- Не перезаписывать и не отменять изменения владельца проекта.

Если решение требует изменений за пределами первоначальной задачи, сначала объяснить причину и согласовать их с владельцем.

## 3. Выполнение задач

Для небольших локальных исправлений можно сразу приступать к работе после изучения контекста.

Для крупных задач:
1. Изучить требования и текущую реализацию.
2. Кратко предложить план изменений.
3. Согласовать план с владельцем.
4. Выполнить согласованные изменения.
5. Проверить результат.

Не считать дополнительные улучшения частью задачи, если владелец их не запрашивал.

## 4. Проверка результата

После выполнения задачи запускать подходящие проверки, если это возможно:

- `npm run lint`
- `npm run build`

Исправлять ошибки, вызванные собственными изменениями. Не исправлять посторонние проблемы без согласования.

В итоговом сообщении указывать, что изменено, какие файлы затронуты и какие проверки выполнены. Если проверки не запускались или завершились ошибкой, сообщать об этом явно.

## 5. Приоритет

Главный принцип работы — **сначала понять задачу, затем решить её минимально необходимыми изменениями, сохраняя существующий код и согласованные решения проекта**.

Предложения по улучшению допустимы, но не дают разрешения на самостоятельное расширение объёма задачи.
